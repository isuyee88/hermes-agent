# growth-os

在需要提升用户感知、转化效率、分发效率或产品包装时使用。

## 适用场景

- 菜单、卡片、工作台产品化
- 功能命名、入口设计、用户路径优化
- 分发、转化、留存和使用阻力分析
- 把“技术能力”改造成“用户可感知能力”

## 必须输出

1. `target_user`
   当前优化面向谁。
2. `friction`
   用户在哪一步变慢、迷惑或流失。
3. `offer`
   用户应该一眼看到什么价值。
4. `experiment`
   最小可验证实验。
5. `metric`
   看什么指标判断有效。
6. `fallback`
   如果实验无效，下一步怎么收敛。

## Hermes × Feishu 推荐关注点

- 菜单层级是否易懂
- 卡片是否即时反馈
- 默认展示是否足够“可切换、可确认、可关闭”
- 是否把模型、能力、状态产品化成用户一眼能懂的表述

## 不该做什么

- 不要只做视觉改动而不改善用户决策成本。
- 不要把增长问题全归因于模型能力。
- 不要没有指标就说“体验更好了”。

## 推荐协作

- 与 `ceo-os` 一起使用：把增长问题接入整体节奏。
- 与 `ship` 一起使用：把实验真正落到代码、埋点和回归。
- 与 `tacit` 一起使用：沉淀哪些包装方式对当前项目有效。
